# Deployment

## Option A — Render.com (free, simplest)
1. Push this repository to GitHub (see `SUBMISSION_GUIDE.md`).
2. Render dashboard -> **New + -> Blueprint** -> select the repo. Render reads `render.yaml`.
3. When asked, enter `ROOT_PASSWORD` and `DEMO_PASSWORD` (pick your own strong values).
4. Wait for the build. Your URL looks like `https://cars-dealership-xxxx.onrender.com` — this is your **deploymentURL**.

Notes
- The free tier sleeps when idle (first request can take ~50 s) and its disk is **ephemeral**: on every restart the
  database is rebuilt and re-seeded, so reviews you post disappear after a restart/redeploy. Take the deployed
  screenshots (Tasks 25-28) in one sitting.
- `SECRET_KEY` is generated by Render; `DEBUG` is `False`; HTTPS origins are trusted automatically.

## Option B — IBM Cloud Code Engine (as in the course)
```bash
docker build -t <your-dockerhub-user>/cars-dealership:1 .
docker push <your-dockerhub-user>/cars-dealership:1
ibmcloud ce project select -n <your-project>
ibmcloud ce application create --name dealership --image docker.io/<your-dockerhub-user>/cars-dealership:1 \
  --port 8000 --env DEBUG=False --env SECRET_KEY=<random> --env ROOT_PASSWORD=<pw> --env DEMO_PASSWORD=<pw> \
  --env CSRF_TRUSTED_ORIGINS=https://<app-url-after-first-deploy>
```
Then `ibmcloud ce application get --name dealership` shows the public URL. (Set `CSRF_TRUSTED_ORIGINS` to that
URL with `ibmcloud ce application update` so the Django admin login works over HTTPS.)

## Option C — Any Docker host (Fly.io, Railway, Azure, ...)
The container listens on `$PORT` (default 8000) and needs only the environment variables above.
